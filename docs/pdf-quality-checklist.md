# PDF品質評価基準・チェックリスト (v0.1-alpha)

本ドキュメントは、`md-tech-pdf` によって生成されるPDFドキュメントの実務利用品質を客観的に評価するための品質基準および評価結果チェックリストです。実務レベルの技術設計書（`examples/real-world/system-design.md`）を用いて評価を実施しています。

## 評価基準の定義

各評価項目は以下の4段階で判定します。

- **A**: 問題なし。印刷・提出用ドキュメントとして十分な品質。
- **B**: 軽微な問題あり。実務利用は可能だが、今後の改善が望ましい。
- **C**: 明確な問題あり。レイアウト調整や手動修正が必要。
- **D**: 実利用不可。文字欠落、図表破損、判読不能など致命的な不具合。

## カテゴリ別詳細評価

### 1. ページレイアウト

- **評価**: A
- **確認項目**:
  - [x] A4サイズ（210mm × 297mm）内にすべての要素が整然と収まっている
  - [x] 上下左右の余白（15mm）が全13ページを通じて均一に維持されている
  - [x] 不自然な空白ページ（空のページ）が生成されていない
  - [x] ページ末尾の極端な巨大空白は発生していない（大きな図の直前を除く）

### 2. 見出し

- **評価**: B
- **確認項目**:
  - [x] H1（文書表題）、H2（章）、H3（節）、H4（項）がフォントサイズと太さで明確に区別できる
  - [x] 見出しと直後の本文・要素とのマージンが自然である
  - [ ] ページ末尾に見出しだけが残り、コンテンツが次ページに送られる現象（Orphan Heading）が発生しない
    - _指摘_: 7ページ目末尾で「6. バッチ処理設計」「6.1 日次請求集計バッチフロー」の見出しだけが残り、図本体が8ページ目へ送られている。

### 3. 本文

- **評価**: A
- **確認項目**:
  - [x] 日本語（漢字・ひらがな・カタカナ）が適切なフォント（システム標準日本語フォント）で美しくレンダリングされている
  - [x] 本文のフォントサイズおよび行間（line-height）が長文読解に適している
  - [x] 3〜5行程度の長文段落でもテキストの揃えが美しい
  - [x] 改ページをまたいだ段落の文章も自然に読み進められる

### 4. リスト

- **評価**: A
- **確認項目**:
  - [x] 箇条書き（ul）のマーカー（・、○、■等）とインデントが正確である
  - [x] 1階層、2階層、3階層の深さの違いが視覚的に明瞭に識別できる
  - [x] 番号付きリスト（ol）の番号インクリメントおよびマージンが正常である

### 5. 表（テーブル）

- **評価**: B
- **確認項目**:
  - [x] 4〜5列の通常サイズ表がページ幅に美しく収まり、ヘッダー背景や境界線が綺麗に出力されている
  - [x] セル内の文字サイズ・行送りが読みやすい
  - [ ] 横に長い表（8列）で各列の幅配分が均等になり、日本語テキストが不自然に1文字ずつ縦書き状に折り返されない
    - _指摘_: 4〜5ページ目の「5.2 トランザクションテーブル物理定義書」において、「論理名」列が狭くなり「ク/シ/ョ/ン/I/D」「加/盟/店/識/別/子」と縦一列に折り返されている。
  - [ ] 20行以上の長い表がページをまたぐ際、次ページの先頭に表ヘッダー（`<thead>`）が再描画される
    - _指摘_: 5ページ目および7ページ目において、前ページから継続する表の先頭にヘッダー行が表示されない。

### 6. コードブロック

- **評価**: B
- **確認項目**:
  - [x] 等幅フォント（Monospace）で表示され、ソースコードのインデントが完全に維持されている
  - [x] コードブロックの背景色および角丸ボーダーがPDF上に正確に出力されている
  - [ ] 1行が極端に長いコード（200文字超）において、末尾の文字が欠落・切断されずに視認できる
    - _指摘_: 7ページ目のSQLおよび10ページ目のTypeScriptにおいて、極長行の末尾がコードブロックの右枠外へ切れて不可視となっている（CSSでの折り返しまたはフォント縮小が未設定）。

### 7. URL

- **評価**: A
- **確認項目**:
  - [x] 150文字を超える長大エンドポイントURLが、右マージンを突破せず適切な位置で自動改行されている
  - [x] 本文のレイアウト枠を破壊していない

### 8. Mermaidダイアグラム

- **評価**: A
- **確認項目**:
  - [x] SVGベクターグラフィックスとして出力され、高解像度印刷でも劣化がない
  - [x] フローチャート（横長・縦長）、シーケンス図のすべての文字・ボックスが鮮明に読める
  - [x] `width`、`height`、`fit=contain`、`align=center` / `align=right` などの配置属性が忠実に反映されている
  - [x] 図が途中で上下に切断されることなく、1枚の図として完全に配置されている

### 9. PlantUMLダイアグラム

- **評価**: A
- **確認項目**:
  - [x] SVGベクターグラフィックスとして出力され、線画・文字ともに極めて鮮明である
  - [x] 日本語のエンティティ名・メッセージ・ノートが文字化けなく綺麗に表示されている
  - [x] 複数エンティティからなるクラス図（5.1）、5者間シーケンス図（6.2）、コンパクトなコンポーネント図（13.2、`align=left`）がすべて仕様通り配置されている

### 10. ページ境界（ページネーション）

- **評価**: B
- **確認項目**:
  - [x] ダイアグラム（SVG）の画像自体がページをまたいで上下真っ二つに分断される現象は発生していない
  - [x] 表のセル内で文字が上下に真っ二つに切断される現象は発生していない
  - [ ] 改ページ直前の見出し孤立（Orphan Heading）が抑止されている
  - [ ] 大きな縦長図の直前で、前ページ下部に生じる空白領域が最小化されている

## 発見された課題一覧 (Issues Found)

今回の品質評価により発見された改善課題です。※設計ルールに基づき、本工程では修正を行わず記録と優先順位付けにとどめます。

### Issue 1: 多列テーブルにおける列幅自動調整と日本語折り返しの最適化

- **Severity**: Medium
- **現象**: 8列の横長テーブルにおいて、列幅の自動配分により特定の日本語列（論理名など）が極端に狭くなり、1文字ずつ縦一列に折り返されて行高が著しく伸びる。
- **発生箇所**: 4〜5ページ目（5.2 トランザクションテーブル物理定義書）
- **推奨対応策**: `table { table-layout: auto; }` のマージン調整、`th, td { word-break: break-word; hyphens: auto; }` または最小列幅（`min-width`）のCSS設定。

### Issue 2: 改ページをまたぐ表でのヘッダー再描画 (`thead { display: table-header-group; }`)

- **Severity**: Low
- **現象**: 20行を超える長い表が改ページされた際、2ページ目以降の先頭に `<thead>` が繰り返し表示されないため、列の判別がしづらくなる。
- **発生箇所**: 5ページ目、7ページ目
- **推奨対応策**: Chromiumの印刷用CSSとして `thead { display: table-header-group; }` および `tr { page-break-inside: avoid; }` のスタイルを適用。

### Issue 3: コードブロック内の超長大行における文字折り返し・クリッピング

- **Severity**: Medium
- **現象**: コードブロック（pre/code）内で1行の文字数が非常に多い場合、折り返されずにコード枠の右端で文字が切断され、読めなくなる。
- **発生箇所**: 7ページ目（SQL）、10ページ目（TypeScript）
- **推奨対応策**: 印刷用スタイルとして `pre code { white-space: pre-wrap; word-break: break-all; }` を設定し、印刷時にコード行が枠外へ飛び出さず自動折り返しされるようにする。

### Issue 4: ページ末尾における見出しの孤立抑止 (`break-after: avoid`)

- **Severity**: Medium
- **現象**: ページ下部に見出し（H2/H3）が配置され、その直後の図やコードブロックが次ページへ送られた結果、ページ最下部に見出しのテキストだけが取り残される。
- **発生箇所**: 7ページ目末尾（「6. バッチ処理設計」「6.1 日次請求集計バッチフロー」）
- **推奨対応策**: CSSに `h1, h2, h3, h4 { break-after: avoid; page-break-after: avoid; }` を適用し、直後の要素と一緒に改ページされるようにする。

### Issue 5: 縦長図（height=150mm超）配置時の前ページ空白の最適化

- **Severity**: Low
- **現象**: 縦の長さが大きい図（A4の半分以上）が存在する場合、ページ内に収まらないため丸ごと次ページに送られ、前ページ下部に空白ができる。
- **発生箇所**: 7ページ目
- **推奨対応策**: 現状でも図の破損を防ぐ観点からは実用上問題ないが、将来的に自動縮小スケール機能やページネーション最適化ロジックの導入を検討。
