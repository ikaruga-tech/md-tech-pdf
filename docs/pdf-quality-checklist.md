# PDF品質評価基準・チェックリスト (v0.1-alpha / 改善後)

本ドキュメントは、`md-tech-pdf` によって生成されるPDFドキュメントの実務利用品質を客観的に評価するための品質基準および評価結果チェックリストです。実務レベルの技術設計書（`examples/real-world/system-design.md`）を用いて評価・再検証を実施しています。

## 評価基準の定義

各評価項目は以下の4段階で判定します。

- **A**: 問題なし。印刷・提出用ドキュメントとして十分な品質。
- **B**: 軽微な問題あり。実務利用は可能だが、今後の改善が望ましい。
- **C**: 明確な問題あり。レイアウト調整や手動修正が必要。
- **D**: 実利用不可。文字欠落、図表破損、判読不能など致命的な不具合。

## カテゴリ別詳細評価

### 1. ページレイアウト

- **評価**: A
- **確認項目**:
  - [x] A4サイズ内にすべての要素が整然と収まっている
  - [x] 上下左右の余白が全ページを通じて均一に維持されている
  - [x] 不自然な空白ページ（空のページ）が生成されていない
  - [x] ページ末尾の極端な巨大空白は発生していない

### 2. 見出し

- **評価**: A（Bから改善）
- **確認項目**:
  - [x] H1（文書表題）、H2（章）、H3（節）、H4（項）がフォントサイズと太さで明確に区別できる
  - [x] 見出しと直後の本文・要素とのマージンが自然である
  - [x] ページ末尾に見出しだけが残り、コンテンツが次ページに送られる現象（Orphan Heading）が解消された
    - _確認結果_: `h1 + *, h2 + *, h3 + *, h4 + * { page-break-before: avoid; break-before: avoid; }` の適用により、見出し直後の解説段落まで同一ページに保持され、孤立見出しが根絶された。

### 3. 本文

- **評価**: A
- **確認項目**:
  - [x] 日本語（漢字・ひらがな・カタカナ）が適切なフォント（システム標準日本語フォント）で美しくレンダリングされている
  - [x] 本文のフォントサイズおよび行間（line-height）が長文読解に適している
  - [x] 3〜5行程度の長文段落でもテキストの揃えが美しい
  - [x] 改ページをまたいだ段落の文章も自然に読み進められる

### 4. リスト

- **評価**: A
- **確認項目**:
  - [x] 箇条書き（ul）のマーカーとインデントが正確である
  - [x] 1階層、2階層、3階層の深さの違いが視覚的に明瞭に識別できる
  - [x] 番号付きリスト（ol）の番号インクリメントおよびマージンが正常である

### 5. 表（テーブル）

- **評価**: B（B維持・視認性大幅改善）
- **確認項目**:
  - [x] 4〜5列の通常サイズ表がページ幅に美しく収まり、ヘッダー背景や境界線が綺麗に出力されている
  - [x] セル内の文字サイズ・行送りが読みやすい
  - [x] 横に長い表（8列）で各列の幅配分が改善され、日本語テキストが極端な1文字縦並びにならない
    - _確認結果_: セルパディングの最適化（`0.5rem 0.6rem`）と `table-layout: auto`、`overflow-wrap: anywhere; word-break: normal;` により、「トランザ」「クション」「ID」「加盟店識」「別子」と単語まとまりで折り返され、大幅に可読性が向上した。
  - [ ] 20行以上の長い表がページをまたぐ際、次ページの先頭に表ヘッダー（`<thead>`）が再描画される
    - _現状_: 今回はLow Severityとして対応を留保したため、ヘッダー再描画は未適用。実用上は読解可能。

### 6. コードブロック

- **評価**: A（Bから改善）
- **確認項目**:
  - [x] 等幅フォント（Monospace）で表示され、ソースコードのインデントが完全に維持されている
  - [x] コードブロックの背景色および角丸ボーダーがPDF上に正確に出力されている
  - [x] 1行が極端に長いコード（200文字超）において、末尾の文字が欠落・切断されずに視認できる
    - _確認結果_: `pre { white-space: pre-wrap; overflow-wrap: anywhere; word-break: normal; }` により、枠の右端で適切に折り返され、文字クリッピングが完全に解消された。通常の短行コードのインデントや可読性は損なわれていない。

### 7. URL

- **評価**: A
- **確認項目**:
  - [x] 150文字を超える長大エンドポイントURLが、右マージンを突破せず適切な位置で自動改行されている
  - [x] 本文のレイアウト枠を破壊していない

### 8. Mermaidダイアグラム

- **評価**: A
- **確認項目**:
  - [x] SVGベクターグラフィックスとして出力され、高解像度印刷でも劣化がない
  - [x] フローチャート（横長・縦長）、シーケンス図のすべての文字・ボックスが鮮明に読める
  - [x] `width`、`height`、`fit=contain`、`align=center` / `align=right` などの配置属性が忠実に反映されている
  - [x] 図が途中で上下に切断されることなく、1枚の図として完全に配置されている

### 9. PlantUMLダイアグラム

- **評価**: A
- **確認項目**:
  - [x] SVGベクターグラフィックスとして出力され、線画・文字ともに極めて鮮明である
  - [x] 日本語のエンティティ名・メッセージ・ノートが文字化けなく綺麗に表示されている
  - [x] 複数エンティティからなるクラス図、5者間シーケンス図、コンパクトなコンポーネント図（`align=left`）がすべて仕様通り配置されている

### 10. ページ境界（ページネーション）

- **評価**: B（B維持・改善）
- **確認項目**:
  - [x] ダイアグラム（SVG）の画像自体がページをまたいで上下真っ二つに分断される現象は発生していない
  - [x] 表のセル内で文字が上下に真っ二つに切断される現象は発生していない
  - [x] 改ページ直前の見出し孤立（Orphan Heading）が抑止された
  - [ ] 大きな縦長図の直前で、前ページ下部に生じる空白領域が最小化されている
    - _現状_: `break-inside: avoid` による図の切断防止の安全側挙動として、A4縦の半分超の図は丸ごと次ページに送られるため、前ページ下部に余白が生じる（Low Severityとして留保）。

## 課題対応状況 (Issues Status)

### 改善完了課題 (Resolved)

1. **ページ末尾における見出しの孤立（Orphan Heading）**
   - **Severity**: Medium
   - **対応内容**: `h1 + *, h2 + *, h3 + *, h4 + *, h5 + *, h6 + *` に `page-break-before: avoid; break-before: avoid;` を適用。見出しとその直後の要素が泣き別れになる現象を解消。
   - **ステータス**: Resolved (A評価)

2. **コードブロック内の超長大行における文字クリッピング**
   - **Severity**: Medium
   - **対応内容**: `pre` に `white-space: pre-wrap; overflow-wrap: anywhere; word-break: normal;` を適用し、`pre code` に `white-space: inherit; overflow-wrap: inherit;` を継承。通常のインデントを維持しながら、枠外はみ出しのみを自動折り返し。
   - **ステータス**: Resolved (A評価)

3. **多列テーブルにおける列幅配分と日本語縦1文字折り返し**
   - **Severity**: Medium
   - **対応内容**: `table` に `table-layout: auto;`、セルに `padding: 0.5rem 0.6rem;`（パディング最適化）、`overflow-wrap: anywhere; word-break: normal;` を適用し、`th` に `word-break: keep-all;` を設定。1文字縦並びを解消し、単語まとまりでの折り返しを実現。
   - **ステータス**: Resolved / Mitigated (実務可読性確保)

4. **フォントカスタマイズ（Google Fonts / ローカルフォント）の検証と品質**
   - **Severity**: Feature Validation
   - **対応内容**: Front Matter の `style.font` による Noto Sans JP（本文）および Roboto Mono（コード）のGoogle Fonts適用、ならびに Hiragino Sans / Menlo のローカルフォント適用を検証。`document.fonts.ready` 待機によりWebフォントの描画完了後にPDF化され、文字欠落やかすれ、文字化け等のない極めて鮮明で高品質なベクターPDF出力を確認。
   - **ステータス**: Resolved (A評価)

### 将来検討課題 (Retained as Low Severity)

1. **改ページをまたぐ表でのヘッダー再描画 (`thead`)**
   - **Severity**: Low
   - **理由**: 表自体のデータは読解可能であり、v0.1正式版以降での機能拡張（CSS paged media対応）として検討。

2. **縦長図（height=150mm超）直前の前ページ下部余白**
   - **Severity**: Low
   - **理由**: 図自体の上下切断を防ぐための安全側挙動であり、ドキュメントの正確性を最優先とするため現状維持。
